## Context

Agentic workflows built over go-lispico need execution that survives process restarts and long human waits, but the kernel must not own infrastructure. The motivating gaps are concrete code: `plugins/agent/plugin.go:206-234` fans out bounded parallel work in a single process pass and loses completed branches when that pass is interrupted; `plugins/fsm/machine.go:204-216` serializes current state only, so a restart resumes from a snapshot with no execution history to replay. The change fixes the boundary on paper: durables, retries, models, tools, storage, and permissions move to an external host-owned engine, and the Lisp layer defines the validated graph that engine executes. Parent record: ADRs `docs/adr/0014-host-owned-workflow-boundary.md`, `0015-independent-branches-bounded-loops.md`, `0016-segregated-persistence-contracts.md`, `0017-temporal-first-adapter.md`, all `status: proposed`, plus research corrections in `docs/research/awl.md`.

## Decisions

- **The specs stay declarative and split three ways.** `specs/workflow-graph/spec.md` pins the portable contract (validation, independent branches, declared joins, bounded loops, patch-bound approval); `specs/host-contracts/spec.md` pins the six declared guarantees per segregated persistence contract; `specs/temporal-adapter/spec.md` pins only the first adapter's mapping behind those neutral contracts. The split is deliberate: a second durable engine must be admissible without touching the graph definition, so adapter specifics never leak into the first two specs.
- **No design beyond these records.** The proposal's six What-Changes bullets, the four parent ADRs, and the spego decision artifact `host-owned-workflow-execution-decisions` (six calls, `status: proposed`) carry the rationale; nothing here adds a call the specs and ADRs do not already record.
- **The host-primitive requirement is read whole.** `specs/workflow-graph/spec.md` requirement "Workflow capabilities stay within host-registered primitives" ends with the network-management draft error-code clause: error codes defined by a network-management extension draft are not base MCP codes and are not treated as such (draft-zw-opsawg-mcp-network-mgmt-00). Any earlier reading that truncated that clause is superseded by this sentence.
- **Traceability is tasks 1.5, 2.5, 3.6 and 4.1-4.4 as written.** Those seven boxes verify every scenario against ADRs 0014-0017 and trace every normative claim to a parent decision; no claim ships untraced.

## Non-goals

- No production code, no adapter module, no `go.mod` change in this change; the Temporal module and its own `go.mod` are later work. Root module stays `go 1.24.0` (`go.mod:1-3`).
- `plugins/agent` and `plugins/fsm` stay frozen; the proposal names their current gaps as motivation, not as work.
- No second engine mapping, no CEL claim beyond the spec's corrected wording, no transport beyond stdio and Streamable HTTP.
