## Context

`workflow-graph` requires every node to reach the world only through a host primitive behind the host permission layer (`openspec/specs/workflow-graph/spec.md:146`), but no specification states what that layer enforces. Separately, `workflow-graph` binds an approval to the reviewed patch's digest (`:115-142`) while `temporal-adapter` implements approval as a Signal plus a deadline with no digest (`openspec/specs/temporal-adapter/spec.md:41-49`). Both gaps sit behind the same boundary ADR 0014 draws: world-touching surfaces are host-registered primitives.

## Decisions

### Enforcement is declared per capability in `host-contracts`

Each clause is a declaration a host either satisfies or rejects, evaluated by the host and never by workflow code. No clause requires the interpreter to own infrastructure, so `plugins/fsm` and `plugins/agent` are not extended: `fsm` is consumer-gated with no consumer, `agent` is frozen, and durability belongs to the engine per ADR 0014.

### The clauses arrive as `## ADDED Requirements` on existing capabilities

`host-contracts` and `temporal-adapter` already exist under `openspec/specs/`. The deltas add requirements without restating archived ones, so no existing scenario is re-pinned or weakened, and both deltas carry no `## MODIFIED Requirements`.

### Taint separation and the patch-digest binding are complementary

The digest blocks unauthorized mutation of a reviewed patch. Taint blocks exfiltration of secrets through a context that also handles untrusted input. They cover different threats, so the change adds taint propagation clauses and the adapter digest carry together rather than choosing one.

### Research-document closure is a task, not a capability delta

`docs/research/awl.md` is a source document, not an OpenSpec capability. Its six unwritten rules become tasks in this change so the gap stays tracked, but no spec delta is created for the document itself.

### The digest is a content binding, not a run identity

`workflow-graph` binds an approval to the digest of the reviewed patch and to the recorded outcome (`openspec/specs/workflow-graph/spec.md:115-142`). Two runs reviewing identical patch content therefore produce identical digests, so the digest cannot by itself tell an approval belonging to this run from one belonging to an earlier run. The adapter delta is written accordingly: the matching-digest scenario takes a Signal delivered to the waiting approval the adapter holds a record of, and the stale-approval scenario takes a Signal that matches no approval record of the receiving run. The two scenarios differ in their input, not only in their outcome, so both hold at once.

### The requirements are written as deltas and land at archive

Apply writes the requirements into this change directory only, at `specs/host-contracts/spec.md` and `specs/temporal-adapter/spec.md`, and writes nothing under `openspec/specs/`. The canonical capability specs receive the requirements when the deltas are applied to them at archive. Writing to the canonical specs during apply would leave a rejected change with requirements already in force.

## Consequences

- Enforcement is declarative and testable per capability, independent of any workflow definition.
- A host that cannot satisfy a declared control rejects the capability instead of degrading silently.
- Taint labels add per-value cost to state channels; that cost is accepted because laundering taint through aggregation is the failure mode the OWASP agentic scenarios describe.
